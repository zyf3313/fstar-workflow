# {{task_title}} 验收标准

澄清收尾时由主 Agent 从目标与用户原话转成可判断的标准，写入任务根目录。每条标准回答：为什么有这条、什么场景期望什么、如何检查、要什么证据、判定边界在哪里。计划与执行引用标准编号，不重写要求；标准跟需求走，修订需记原因。

每条标准必须标明「判定方式」：`machine`（可由测试命令、独立检查或来源核实客观判定）或 `user-judgment`（需要用户判断）。含任何 `user-judgment` 条目的任务不得走自验收规则，必须由用户亲验。

<!-- fstar:item:A-001:start -->
### A-001 标准名称

- 依据：用户原话引用（“……”）或确认结论出处。
- 场景与期望：什么条件下应当观察到什么结果。
- 判定方式：machine / user-judgment。machine 需写明可客观复核的判定来源（测试命令、独立检查或来源核实）；user-judgment 需写明留给用户判断的问题。
- 检查方法：实测 / 来源核实 / 对照检查 / 用户判断，按成果类型选择。
- 证据要求：需要的证据形式与来源日期；无法核实时标“未验证”，不推测。
- 判定边界：什么算满足、什么不算（例如仅部分能力达成不视为满足）。

### A-002 示例：数据可导出

- 依据：用户原话“不希望以后搬不出来”。
- 场景与期望：内容（正文及关联部分）可导出为通用格式。
- 判定方式：machine（官方导出说明 + 实际导出验证，输出可客观核对）。
- 检查方法：官方导出说明 + 实际导出验证。
- 证据要求：导出格式清单与来源日期；只导出正文不算完整满足。
- 判定边界：正文可导出但其余部分不能，判为部分满足并说明缺口。
