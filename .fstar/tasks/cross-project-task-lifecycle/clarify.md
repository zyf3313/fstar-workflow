# 澄清记录

## 背景与目标

用户要求上一批验收合入 main 后，将自然语言确认措辞与多仓库、数据存放、验收中阶段、分支定位一起作为新任务处理。

## 已核实事实

- TaskStore 当前把数据根固定为 project_root/.fstar；find_project_root 根据仓库内 .fstar/.schema-version 发现项目。
- children 对应本任务目录下 subtasks 的实际目录；related_tasks 当前指向同一项目归档中的任务，不是跨仓库执行关系。
- new_task 已包含 branch/base_branch/worktree_path/commit/pr_url，但 start 未填充分支；current 按项目和 session 指针查找，没有分支匹配回退。
- awaiting_acceptance 是证据服务的派生状态，phase 仍为 planning/in_progress/completed。

## 决策树与前沿

用户已确定本轮范围与两项关键取舍，当前没有阻塞实现的产品问题。实现遇到改变这些约束的选择时返回澄清，不能默默扩大范围。

## 已确认结论

- 一仓库主任务协调其他仓库的本地任务，记录仓库位置和双向关联。
- 每个仓库读取自己的规范；没有初始化时进入初始化流程。
- 新增验收中正式阶段；检查通过进入该阶段，用户验收后完成。返工可回规划再执行。
- 任务绑定分支以便 QA 定位；歧义由用户选，不要求重新叙述整个任务。
- 用户侧使用自然语言确认，由 agent 内部记录真实原话并执行命令。
- 跨仓库验收选择：用户选择“统一确认（推荐）”。各仓库子任务进入验收中，主任务汇总联合验证；一次确认明确覆盖的主子交付版本。
- 数据存放选择：用户选择“三种模式（推荐）”。项目内共享（默认）、项目内仅本机忽略、全部存用户目录；本轮不做混合模式。

## 设计建议（实现默认值，不冒充用户原话）

- 用户目录采用可读名称加稳定 UUID；仓库路径作为可重新绑定的定位信息，不能仅用 basename 或 remote URL 合并身份。
- 不自动切换、合并或重置用户 Git 分支。分支索引包含项目和工作树。
- 主任务完成前验证本次涉及子任务的状态和新鲜证据；目标仓库不可用时明确阻塞；跨根写入需恢复方案。
- 旧数据保持可读；迁移不可静默删改旧目录。归档任务保持不可变，通过关联修复任务继续。
