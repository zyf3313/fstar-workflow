# 全局资源管理与 Magpie 集成：产品需求

## 1. 背景与范围

需求作者为用户，权威来源为本任务 clarify.md「已确认需求」及其引用的用户原话；执行拆分来源为 plan.md。本文按 resources/templates/doc/prd.md 及其 mapping 整理，属于待评审草稿，不表示用户已接受本文、代码或交付。

用户希望资源统一按全局版本管理，项目只保留任务、规范及身份配置；一次全局更新后，已迁移项目随全局版本工作，无须逐项目更新。用户追加：

> 好 没问题 ，然后再加个安装初始化相关的因为现在有好多用户都有magpie这个app 在安装的时候能不能写个脚本做个将 skills还有hooks还有agets工作流里面的都集成到 magpie里面 如果发现用户没有magpie这个app就不用做了

经公开 CLI 核实，Magpie 可接管 skills，但没有已核实的通用 hook 或子 agent 定义导入能力。因此 skills 使用公开能力接入，hooks/子 agents 使用编码工具原生全局配置共存。该边界与 clarify.md 一致。

## 2. 业务流程

1. 安装或更新：默认面向全局资源及对应宿主入口，检查所有权与完整性；安装/初始化时检测可选 Magpie 接入能力，缺失正常跳过。
2. 打开项目会话：SessionStart 只读比较项目遗留资源、有效版本及全局完整性；需要迁移时，向用户自然语言说明影响并询问。
3. 用户同意：显式迁移操作预览改动、保护冲突、备份并迁移可确认归属的资源；用户延后：显式 runtime 操作记录项目与目标版本的决定。
4. 后续启动：已迁移项目跟随全局；同会话 clear/compact 或双 hook 不重复注入迁移提示；已记录延后的同一项目与目标版本不重复询问，目标版本变化可再次提醒。
5. 失败：全局损坏先诊断，不自动升级、清理或迁移；迁移失败恢复可恢复项并报告剩余冲突；会话已缓存资源时提示重启生效边界。

## 3. 模块与逐功能要求

<!-- fstar:item:R-001:start -->
### R-001 全局默认资源（对应 D-001，计划 P-001）

- 业务结果：新安装和资源更新默认使用全局目标；全局资源与宿主 skills/agents/hooks 版本一致，已迁移项目不再保留覆盖全局的工作流副本或旧 pin。
- 范围与约束：复用现有资源解析和安装机制；项目任务、规范、身份配置保留。显式资源覆盖与未迁移旧 pin 不应被静默改写，需纳入迁移判断。资源更新与数据 schema 迁移分别检查、分别执行。
- 验收：给定多个已迁移项目，更新一次全局资源后，新会话使用同一全局目标版本；项目任务与规范不变。给定新项目，初始化不再默认生成项目级工作流资源副本。给定全局不完整，报告实际有效来源与诊断，不把回退结果称为更新成功。
<!-- fstar:item:R-001:end -->

<!-- fstar:item:R-002:start -->
### R-002 旧项目迁移保护（对应 D-002，计划 P-001）

- 业务结果：旧项目经用户真实对话同意迁移到全局管理，能够核对修改范围并恢复失败。
- 规则：使用所有权记录和指纹识别旧副本、hook 注册与 pin；修改前备份。用户修改、同名用户文件、无法证明归属的配置保留并作为冲突报告；其他配置不动。尚未解决的覆盖项不得被宣称已迁移完成。
- 验收：给定未改动的受管副本与旧 pin，确认后迁移并记录备份，重复执行不重复增删；给定用户修改或未知所有权，保留原内容并报告。注入中途失败后可恢复本次受管改动，不破坏用户数据。不同意迁移时只记录明确的提醒决定，不改变项目资源。
<!-- fstar:item:R-002:end -->

<!-- fstar:item:R-003:start -->
### R-003 会话只读比较与不重复提醒（对应 D-003，计划 P-002）

- 业务结果：旧项目在会话启动时获得可理解的迁移建议，不被反复打扰。
- 规则：SessionStart 检查遗留资源、有效版本和全局完整性，检查本身不写项目、任务、资源或提醒决定。提醒去重需要真实机制：同会话去重与明确延后决定由显式 runtime 操作记录，持久决定按项目身份和目标版本区分。双 hook、clear/compact 不重复注入；新目标版本可再次提示。
- 边界：不得声称只读 hook 已保存决定；仅提示不代表迁移授权。无初始化项目时不给出虚假的项目迁移结果，现有 helper hook 仍可能输出最小工作流上下文。资源已缓存时说明需要重启；全局损坏时给诊断与后续操作建议。
- 验收：覆盖无项目、新项目、旧项目、已迁移项目、双 hook、clear/compact、延后后再启动、目标变更、全局损坏和注入预算；只读检查前后项目、任务、资源及 runtime 内容不变，显式提醒操作仅写指定 runtime 数据。
<!-- fstar:item:R-003:end -->

<!-- fstar:item:R-004:start -->
### R-004 可选 Magpie skills 接入及原生入口共存（对应 D-004，计划 P-003）

- 业务结果：安装/初始化可调用脚本或 CLI 完成受支持的接入；未安装 Magpie 时基本 fstar 安装正常完成。
- 规则：检测 PATH 与平台 App 位置，探测版本和公开能力；skills 从 ~/.agents/skills 经公开的命名 hand-over 接管，按能力使用指定技能的 direct 分发。只操作明确属于 fstar 的技能，保持所有权记录、幂等性及冲突保护；升级/卸载不得删除用户或 Magpie 仍管理的未知内容。
- 能力边界：Magpie 的 agents 指编码工具，不是 fstar 子 agent 定义。hooks/子 agents 保持工具原生全局安装；不宣称已导入 Magpie。不得编辑 Magpie 私有 JSON，不改变模型、账号、provider 或其他技能路由。
- 验收：fake CLI 覆盖缺失、App 不在 PATH、旧版/缺能力、超时/失败、成功、重复接入、路径含空格及用户同名文件。失败明确报告接入状态与恢复方法，不阻断基本安装，不把部分成功报告为完整成功；真实用户设置不参与写入测试。

## 4. 跨模块要求与影响

安装器、资源解析、项目初始化、SessionStart、runtime 提醒记录和 Magpie 适配需要共用项目身份、资源目标及所有权事实。更新不应暗中迁移任务/规范 schema，也不能破坏既有状态与证据门禁。宿主优先级、旧副本遮蔽全局及当前会话缓存需作为集成检查对象；未测试的宿主行为不得写成已保证。

本文以文字流程完整描述判断、授权、写入边界和异常恢复，无图示依赖。设计条目 D-001 至 D-005 与同序 R 条目对应；计划 P-001 覆盖 R-001/R-002，P-002 覆盖 R-003，P-003 覆盖 R-004，P-004 覆盖 R-005。
