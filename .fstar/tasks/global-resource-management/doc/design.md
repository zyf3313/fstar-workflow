# 全局资源管理与 Magpie 集成：技术设计

## 1. 理解与范围

需求权威为 clarify.md 中的用户确认及原话，执行范围为 plan.md 的 P-001 至 P-004。本文按 resources/templates/doc/design.md 及其 mapping 整理，与 PRD 的 R-001 至 R-005 一一对应，是实现建议草稿，不表示代码已实现或用户已验收。

现状依据 clarify.md：安装器在已初始化项目内默认写项目宿主目录；resolve_resources 优先显式/项目配置，其次用户版本文件，最后 bundled。目标是默认全局安装和更新，经确认迁移旧项目后跟随全局，同时保留任务、规范及身份配置。资源升级不隐含数据 schema 迁移。

## 2. 总体技术方案与全景流程

安装/更新先解析全局目标和宿主入口，复用现有 ownership、预览、备份与恢复机制。初始化复用该入口。项目启动只读收集有效资源与遗留覆盖项，输出诊断和自然语言迁移建议；对话取得真实同意后才调用迁移入口。明确延后和提醒投递去重通过单独 runtime 操作记录，检查器不承担写入。

Magpie 是可选后续适配步骤：检测可执行文件 → 探测公开能力 → 预览受管技能与冲突 → 通过公开 CLI 接管指定技能 → 核对结果并记录归属。缺失或失败不回滚已经成功的基本 fstar 安装，单独报告接入状态。以上文字覆盖分支、授权及恢复，不使用需要另行解释的图示。

## 3. 实体、状态与存储结构

以下为需落实到既有存储机制的逻辑字段，不预设 Magpie 私有格式或新增任务状态。

| 数据 | 最小内容 | 写入者与用途 |
|---|---|---|
| 全局安装记录 | 资源版本/指纹、受管宿主路径、内容指纹、所有权 | 显式安装/更新；判断一致性与可安全删除范围 |
| 迁移预览与恢复记录 | 项目身份、原 pin/注册项、旧新指纹、备份位置、逐项结果 | 经用户同意的迁移操作；处理冲突、恢复与重入 |
| 只读检查结果 | 有效来源/版本、全局完整性、遗留项、迁移建议 | 检查器返回；不持久化决定 |
| runtime 提醒记录 | 项目身份、目标版本、会话身份、已投递/明确延后 | 独立显式 runtime 操作；投递去重和延后记忆 |
| Magpie 接入记录 | 指定技能名、暂存来源/指纹、公开命令逐步结果、已确认归属 | 适配操作；区分 fstar 暂存、Magpie 已接管和状态未知 |

项目身份复用现有身份解析，避免只按工作目录去重。runtime 使用既有用户隔离根，不把提醒写进项目或任务。投递记录与延后决定不同：前者不代表用户拒绝或授权。

## 4. 模块技术设计

<!-- fstar:item:D-001:start -->
### D-001 全局安装与资源解析（R-001，P-001）

将 installer 默认目标从项目宿主目录调整为全局资源与对应工具的全局入口；project 初始化复用同一逻辑，避免独立生成新项目副本。显式覆盖继续作为可见输入，旧项目 pin/副本进入迁移检查，不通过调整解析优先级悄悄忽略用户配置。

全局资源与 skills/agents/hooks 从同一交付版本生成，写入前检查 ownership、指纹与冲突，复用现有事务/备份能力。发布完整性校验通过后才报告新版本可用；部分失败报告逐项状态及恢复结果。已迁移项目没有旧覆盖项时由 resolve_resources 跟随全局。全局缺失/损坏时显式显示有效来源和诊断，不能把 bundled 回退称为全局健康。

验证：隔离多个项目，更新一次全局并在新会话解析同一版本；验证新初始化、显式覆盖、旧 pin、损坏全局和数据 schema 不变。现有资源解析调用方均纳入影响检查。
<!-- fstar:item:D-001:end -->

<!-- fstar:item:D-002:start -->
### D-002 所有权迁移、备份与 pin（R-002，P-001）

迁移入口先生成受管文件、项目宿主注册与资源 pin 的逐项预览。所有权记录和当前指纹共同决定能否修改；缺失记录、内容变化、未知同名文件均作为冲突保留。预览本身不写资源，用户真实对话同意后再执行，并在执行前重新核对预览指纹；变化则停止受影响操作并重新报告。

修改前保存可定位备份和恢复信息；只处理已确认归属的旧副本、hook 项和 pin，保留无关 settings 字段与项目任务/规范/身份。无法证明 pin 归属或冲突未解决时不强制清除，也不标记迁移完成。迁移后复查实际解析来源及遗留入口，重复执行已完成项目应无增量变更。

中途失败使用既有恢复机制恢复本次受管改动；恢复也需检查当前指纹，避免覆盖失败期间的新用户修改，无法恢复项明确列出。schema 检查单独报告，不调用数据迁移作为资源迁移的隐含步骤。验证覆盖重复执行、用户修改、pin 冲突、无关配置保留和失败恢复。
<!-- fstar:item:D-002:end -->

<!-- fstar:item:D-003:start -->
### D-003 只读启动检查与显式提醒记录（R-003，P-002）

SessionStart/session-context 调用共享检查逻辑，读取项目身份、有效资源来源、遗留 pin/副本、全局完整性和已有 runtime 决定，输出有预算的诊断/建议；不安装、不清理、不修改项目/任务/资源，也不写 runtime。非初始化目录不产生虚假迁移提示；现有 helper hooks 可以输出最小上下文，不能保证全部静默。

迁移建议经协调层的显式 runtime 提醒操作处理：以项目身份＋目标版本＋会话身份原子检查并记录投递，返回是否展示；同一操作供全局与旧项目入口共用。只有拿到本次展示结果的路径输出迁移询问，clear/compact 保持同一会话键。只读检查产生候选不等于已经投递，不能靠它自动保存决定。写入失败需报告去重不可用，不宣称已记录。

用户明确延后时，另行记录项目身份＋目标版本的延后决定；新会话同目标读取后跳过询问，目标改变重新评估。用户同意时进入 D-002 的显式迁移，不把“已投递”作为同意。重复注册和旧入口行为必须验证；无法参加共享去重的遗留 hook 应被识别为兼容限制，不能仅凭新 hook 的测试声称双 hook 已解决。会话已缓存入口时提示重启。

验证覆盖 PRD R-003 的全部场景，分别断言只读检查零写入、显式 runtime 操作写入边界、双入口并发投递去重以及注入预算。

<!-- fstar:item:D-004:start -->
### D-004 Magpie 公开 CLI 适配（R-004，P-003）

提供可调用的 CLI/脚本适配入口，安装/初始化复用，核心安装逻辑不复制。先查 PATH，再查平台已知 App 位置；本机已核实路径为 /Applications/magpie.app/Contents/MacOS/magpie，版本 0.1.4380。通过有界超时的版本/help 探测确认当前能力，用参数数组调用以支持空格路径，不依赖 shell 字符串拼接。

已核实的公开入口包括 library skill hand-over <name…>（从 ~/.agents/skills 接管）、skill agents、skill router <name> direct、skill how、library sync。具体参数及前置条件以当前版本 help/how 为准；不把这些命令当作任意版本均有的保证，也不从中推断 hook/子 agent 导入能力。

接入按技能名执行：先核对 ~/.agents/skills 中的来源及 fstar ownership；缺少待接管内容时由安装器写入其受管技能，遇用户同名项停止该项。记录接管前指纹，通过公开 hand-over 执行，随后使用可用公开查询/命令结果确认归属；确认成功后记录为 Magpie 管理，避免下一次安装恢复一份竞争副本。若支持，单独对这些命名技能设置 direct；必要的同步步骤按公开说明执行，不能改其他技能路由。

重复执行先检查记录与公开状态；一致则跳过，不能确认归属时报告待核对，不盲目接管。更新 Magpie 已接管技能只采用当前版本公开支持的路径；无安全公开更新/移除能力时明确报告需用户通过 Magpie 操作。fstar 卸载仅删除仍由自己拥有且指纹未变的本地条目，不删 Magpie 管理内容。手动修改、部分接管成功或命令超时后保存逐项事实，重试前重新核对；不假设 Magpie 多条命令具有事务性。

Magpie 缺失正常跳过，能力不足/失败报告降级且不阻断基本安装。hooks/子 agents 继续用宿主全局原生入口；Magpie 的 agents 表示编码工具。禁止私有 library.json/providers.json 编辑以及模型、账号、provider、无关路由变更。fake CLI 覆盖缺失、App 检测、旧版、失败/超时、重复、空格路径、同名冲突和部分成功恢复；不写真实用户配置。

### D-005 验证、文档与交付（R-005，P-004）

按 P-001 至 P-003 分别提供安装/迁移、提醒和 Magpie 的针对性测试；完整链路使用临时 HOME/user/runtime/host 根与 fake CLI，确保 subprocess 继承隔离环境。真实 App 仅允许只读 help/version；若无 live 写入测试，结果明确记录这一限制。

实现验证执行 PYTHONPATH=src python3 -m unittest discover -s tests -t . 及 node --test tests/test_package.cjs。修改 src/ 或 resources/ 后执行 node scripts/build-package.cjs，核验 resources/package-assets.json 的真实性及重复构建无新增变化。README 描述实际 CLI、全局默认、旧项目同意迁移、延后记录、重启边界、Magpie 限制及恢复办法。

独立 check 覆盖全部 R 条目和端到端路径；影响检查同时检查调用方和机制交互，包括配置优先级、双 hook、预算、runtime 隔离、资源与 schema 分离、ownership 交接、卸载和失败恢复。失败修复后重新验证，证据绑定真实交付文件而非目录或仅本文。资源版本遵循现有发布规则，不在设计中指定未经核实的新版本号；实现完成不等于发布。

检查完整后按现有门禁进入 awaiting_acceptance，等待用户确认；不自动 accept、提交、合并或发布，不重试前次 npm 发布。本文只交付文档，不登记 dispatch、不修改 task/meta 状态。

## 5. 专项技术设计

宿主合并必须保留无关字段和用户修改；公共 CLI 调用必须有超时、明确退出状态及逐项结果。runtime 投递写入需要并发保护；Magpie 接管与 fstar 所有权之间没有已证明的跨系统事务，应采用记录、重新核对和保守恢复。相关验证由 D-002 至 D-005 覆盖。

## 6. 迁移、发布与回滚

先实现全局安装和旧项目预览/迁移，再接入启动检查及 Magpie，最后集成验证。回滚依赖受管条目的备份及指纹核对；Magpie 部分操作没有已核实的统一回滚 API，按公开能力恢复或报告人工操作，禁止通过私有 JSON 补救。发布沿用 CONTRIBUTING.md 的验收、分支、版本和 main 发布规则；本次规划不执行发布。

## 7. 影响范围

| 项目模块 | 受影响功能或范围 | 本次改动及检查 |
|---|---|---|
| installer / project / 资源解析 | 默认目标、初始化、pin、更新与卸载 | 统一全局默认，检查覆盖优先级和多项目跟随 |
| runtime/hooks / 宿主注册 | 启动注入、重复 hook、提醒记录 | 分离只读检查与显式 runtime 写入，检查预算和重启 |
| Magpie 适配 / skills | 暂存、接管、命名分发与所有权 | 有界公开 CLI、冲突保护、部分失败重入 |
| tests / README / 交付清单 | 行为契约、操作说明、包完整性 | 隔离测试、全量回归、独立检查与影响检查 |

## 8. 配置与字典

global 表示全局资源目标；legacy 表示仍存在项目 pin 或宿主副本；deferred 表示用户明确延后某项目与目标版本；delivered 仅表示同会话已经展示迁移询问。上述为设计语义，不新增任务状态枚举。命令名、配置字段及 runtime 存储位置由实现复用现有机制后在 README 如实列出，不编造已可调用的新参数。
