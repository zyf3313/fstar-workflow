## Finding F1 — matcher must be a pipe-separated STRING, not array (DEFECT, fixed)

- **Evidence source**: strings extracted from the installed claude
  2.1.316 binary
  (`~/.nvm/.../claude-code/bin/claude.exe`):
  - Official validation doc string: `"Hooks use a matcher + hooks array.
    The matcher is a string: a tool name ("Bash"), pipe-separated list
    ("Edit|Write"), or empty to match all. Example:
    {"PostToolUse": [{"matcher": "Edit|Write", "hooks": [...]}]}"`
  - Runtime consumption: `for(let Et of gt.matcher.split("|").map(...))`
    — matcher is treated as a string and pipe-split.
- **Defect**: `installer.py:_plan_host_settings` wrote
  `"matcher": ["startup","clear","compact"]` (array) — registration plans
  carry lists and the plan builder passed them through. Hosts consuming
  matcher as a string never match an array value. Fixture tests asserted
  the same array shape (test_installer.py), so the gap was invisible
  without a real host; `registration.py` header claimed "verified against
  Claude Code" but this field had never been checked against the real
  binary. The repo's own Trellis hooks use string matchers ("startup",
  "Task", ...) — corroborating.
- **Fix**: serialize at plan build time —
  `matcher = "|".join(shape.get("matchers") or [])`
  (installer.py `_plan_host_settings`). Empty list → `""` (match all).
- **Tests**: fixture matcher literals updated to string form; new
  regression `test_installed_matchers_are_pipe_separated_strings`
  asserts all four events serialize to
  `startup|clear|compact` / `Task|Agent` / `` "" `` / `Edit|Write` and
  every installed matcher is `str`.
- **Result**: full suite 663 tests OK (was 662; +1 regression test).
  Dry-run now emits string matchers for all four entries.

## Finding F2 — launcher lacked executable bit (DEFECT, fixed)

- **Evidence**: real session 1: `Hooks: SessionStart:startup
  [bin/fstar-hook.cjs session-context] finished with status 126`;
  stderr `/bin/sh: .../fstar-hook.cjs: Permission denied`;
  `ls -l` showed `-rw-r--r--`.
- **Cause**: source-tree launchers were never chmod'ed; the installer
  registers the source-tree `bin/` path directly (launcher kind is not
  copied into the user root), so the host executes a non-executable file.
- **Fix applied**: `chmod +x bin/fstar-hook.cjs bin/fstar.cjs` (source
  tree). After fix, hook exit 0 and context injected.
- **Follow-up (hardening, recommended for installer)**: preflight in
  `_hook_command`/plan should verify `os.access(launcher, os.X_OK)` and
  raise a plan conflict instead of registering a dead command; npm
  packaging must preserve the exec bit in the tarball.
