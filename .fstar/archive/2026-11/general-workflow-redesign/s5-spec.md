## 实施合同

1. **公共规则**：`resources/runtime/routing.md` 为公共入口。主/子 Agent 识别当前意图与作用范围，优先用户点名的技能，从宿主暴露的本地技能元数据筛选，读取相关适用规则，实际调用匹配技能后继续任务。阶段仅是上下文。无匹配正常推进；多候选选覆盖目标的合理最小组合，普通选择采用默认，仅重要目标、范围、权限或不可逆决定需询问。
2. **逐轮提醒**：`resources/runtime/prompt-states.md` 与 `src/fstar/runtime/hooks.py` 的 prompt-context 在每轮阶段提示之外提供共用轻量提醒，覆盖 no_task、planning、in_progress、awaiting_acceptance 及完成/无活动任务路径；缺失资源时的降级仍保留提醒。无需注入全部技能正文、重复全盘扫描或硬编码宿主技能目录。意图变更重新判断；同一行动仍有效的技能正文不重复加载。
3. **派发与回执**：现有派发协议和四张角色卡传递选中技能、来源入口、理由及适用子任务。worker 可以补充匹配；不得扩大派发权限或递归启动同一 fstar 行动。已安装、推荐、读取、调用尝试和成功执行应分开表达；未调用必须说明原因，失败如实返回。无匹配允许空列表；旧派发不带技能信息时仍兼容，由 worker 按暴露能力自行判断。
4. **薄能力接口**：会话管理、能力分发、记忆存储、调度触发共用小型可注入接口。只读探测返回可用性及原因；握手确认所需能力及不兼容原因；缺席/失败沿既有路径降级，不自动安装或执行实际操作。探测成功不产生授权。降级分别为主会话（保留原有角色分工）、原生 skills/hooks、既有本地知识存储、手动驱动。
5. **分发兼容**：把已有 `src/fstar/magpie.py` 安装分发接到能力分发接口，保持公开函数签名、返回结构、CLI 和原生安装行为。无 Magpie 时核心仍可运行；运行时技能意图判断不放进安装分发函数。其余外部适配无需在本步实现。

开发选择（非用户原话）：可用 `selected_skills` 表达技能标识/来源/选择理由/行动上下文，用 `skill_usage` 返回实际状态/补选理由/调用回执引用或未调用原因；字段可以映射到现有派发与返回结构。保留当前加载动作的上下文即可，不要求新数据库、持久偏好记录或框架。适配接口的具体 Python 类型和命名由执行者按现有风格选择；可注入 fake adapter 验证合同。

## 交付与检查

确定性测试至少覆盖显式匹配、跨阶段/no_task、无匹配、多候选、worker 传递/回执以及四能力降级；其中匹配判断可使用预置选择结果来验证协议，但须标明 fixture。真实宿主证据另列上述场景的输入、实际暴露技能、版本/来源、调用记录、结果与限制；无匹配场景记录未调用及正常推进。未获取真实记录时写“未验证”，继续可独立完成的测试，不把整个 S-5 报成已验证完成。

执行者自查和独立检查均按条目引用证据；既有最终只读检查及用户验收规则不变。阶段结果写入协调者指定的检查记录，本规格不充当检查报告。此文位于任务根目录，后续交付注册由协调者处理；本次编辑不修改 task.json。
