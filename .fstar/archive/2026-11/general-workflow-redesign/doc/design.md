## 1. 目标与范围

把 fstar 从偏开发、固定步骤的工作流重构为通用事项协作系统：四阶段组织工作，AI 按意图选择阶段内行动；核心独立自足，外部工具经能力接口接入；长期价值在经验循环。

本设计覆盖：模板体系、Skills 与角色卡、task.json schema 扩展、验收协议、路由约束收缩、意图驱动的本地技能选择、四能力薄接口，以及已有 Magpie 安装分发的兼容适配重构。不覆盖：实际调度/事件触发（第一版范围外，C-08）、herdr 集成、新增外部工具集成或 Python 内的 LLM 推理。经验偏好学习仍属 S-6。

## 2. 模板体系整改

现状问题（document-audit.md）：模板只定栏目不定质量；生成结果粒度不稳定；内容重复；状态语义含糊。

| 模板 | 处置 |
|---|---|
| task/plan.md | 重写：整体思路 + 步骤（输入/行动/产出/完成判据/遇阻处理）+ 验证交付 + 调整条件；去掉 Patterns to Mirror 等开发专属栏目 |
| task/clarify.md | 重写：按现有样稿结构（背景原话/事实与来源/确认结论含引语/假设未知/取舍/被替代决定） |
| task/check.md | 保留表格骨架，增加：对照标准编号、三线检查结论（理解/符合/可用）、并行拆分时的分片汇总说明 |
| doc/prd.md、doc/design.md | 从默认模板集移除；转为软件场景的可选参考（位置待定，如 scenarios/software/） |
| plan.mapping.yaml | 随 plan 重写评估：步骤级条目标记是否保留 P-xxx 语义或改为步骤 ID；影响 evidence 快照提取 |
| 新增 task/criteria.md | 验收标准模板：依据/场景期望/检查方法/证据要求/判定边界，每条带用户原话引用 |
| 新增 deliverables 说明 | 交付注册格式（JSON schema 草案见 §4） |

写作规则（进模板注释或共享参考，不另立文档）：详细程度由不确定性和交接需要决定；引用代替重复；计划动作与已验证事实严格分离。

## 4. task.json schema 扩展（草案）

新增字段（全部可选，向后兼容）：

```json
{
  "status": "active | waiting_user | waiting_external | paused",
  "status_detail": {"reason": "...", "since": "..."},
  "work_items": [{"id": "S-1", "state": "done|active|blocked|cancelled",
                   "summary": "...", "evidence_refs": []}],
  "next_step": {"condition": "...", "action": "..."},
  "deliverables": [{"name": "...", "path": "用户偏好位置", "format": "...",
                     "criteria_refs": ["A1"], "version": "..."}]
}
```

- deliverables 在 task.json 内登记指针（替代独立 deliverables.json 文件，减少文件数——与扁平化精神一致；目标结构文档相应简化）。
- phase 四阶段语义不变；status 与 phase 正交。
- work_items 的 S-xxx 与 plan 步骤对应但不强绑定（简单任务无 plan 也可有 work_items）。

兼容评估点：evidence 的 source_snapshot 含 phase/description/templates 哈希——新增字段不影响既有哈希语义（字段在 meta 外层追加）；lease、events 不动；旧任务缺新字段按默认值处理。

## 5. 验收协议

流程：criteria.md（澄清收尾建）→ 执行者自查（引用条目）→ 独立检查（全新实例、三线、可并行）→ 最终检查（只读、不并行、对照原话）→ 用户验收。

- 证据继续内容寻址；失效按条目局部化。
- 打回（rework）从"证据全作废"改为"按标准条目影响范围作废"；全量作废仅限目标/范围变化。**此项改动现有 rework 语义，实现时需单独验证。**
- accepted_via_rule 机制保留，引用格式适配 criteria 条目。

## 6. 意图驱动的技能选择与工具适配层（C-14/C-19/C-23）

S-5 先补公共技能选择，再完成原定工具适配。技能选择由主/子 Agent 结合当前意图、作用范围与授权判断；阶段仅是上下文，覆盖需求澄清、实施、验收、完成及 no_task，不以固定阶段表限制技能。

公共 `resources/runtime/routing.md` 承载统一规则：优先用户点名的技能；从宿主已暴露的本地技能名称、描述及入口筛选候选，读取相关技能适用规则，实际调用匹配技能后继续推进。无匹配按原流程继续；多候选采用覆盖当前目标的合理最小组合，普通歧义不重复追问，仅重要目标、范围、权限或不可逆决定才询问。意图改变重新判断，同一行动已加载且仍适用的技能不重复加载；不得递归进入同一 fstar 行动，不把已安装、推荐或已读取写成已调用。技能可用性不代替本次授权。

`prompt-context` 在每个用户回合提供共用轻量提醒，并保留当前阶段提示；不注入全部技能正文，不逐轮全盘扫描，不硬编码全局技能目录，不绑定 Magpie，不自动安装。派发协议和四张角色卡携带所选技能、入口及理由；worker 按自身子任务补充匹配并遵守同样规则，返回实际调用回执或未调用原因。Python 仅实现上下文与协议传递，不做关键词自动路由或 LLM 推理。

四能力接口以薄接口提供探测、握手与降级；可注入 fake adapter 测试，无需引入新框架。探测报告实际可用性，握手核实所需能力是否受支持，失败/缺席明确给出原因并沿既有路径降级；探测和握手不自动执行操作、不产生授权。

| 能力 | 缺席或握手失败时的降级 |
|---|---|
| 会话管理 | 主会话直接交互，保留既有实施/检查角色与授权边界 |
| 能力分发 | 宿主原生 skills/hooks 与原生安装路径 |
| 记忆存储 | 已有本地知识存储与现有路径解析，不新增存储权威 |
| 调度触发 | 手动驱动；本版只定义接口，不实现调度器 |

已有 `magpie.py` 的安装分发作为能力分发适配实现，保持既有公开函数签名、返回结构和 CLI 兼容；安装分发不承担运行时意图匹配。herdr 不实现集成，外部适配缺席不阻断核心流程。技能调用的经验偏好学习仍留 S-6。

验证分两层：确定性集成测试检查提醒覆盖、选择信息传递、回执与降级，fake 只验证适配合同；真实宿主调用单列已验证/未验证及调用证据，覆盖点名、跨阶段、无匹配、多候选和 worker 使用。字符串断言与模拟回执不能证明语义匹配可靠，也不能替代真实调用。具体判据见 [S-5 规格](../s5-spec.md)。

## 7. 经验循环（概要，详细设计第二优先级）

存储沿用 .fstar/knowledge/ 分层（rules/memory/specs + references/procedures），新增：每条经验带 scope（个人/场景/事项）、置信度（明确要求/推测/已验证）、来源引用、失效条件。检索按当前事项的意图和范围过滤注入，不全量注入。用户可问"为什么这样做"并要求修正/停用。纠错、过期、退出机制先于新增存储实现。

每步独立可验收；1-3 为第一版核心（C-08），4-6 按价值排序后续推进。
