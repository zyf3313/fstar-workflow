### A-001 通用四阶段与运行状态兼容

- 依据：C-01（通用四阶段）、C-06（task.json 唯一状态权威）、C-17（运行状态/工作项/下一步），见 [澄清记录](clarify.md)；计划 [S-2](plan.md)。
- 场景与期望：任意事项以需求澄清、实施、验收、完成推进；旧 task.json 无需迁移即可读写，新 status/status_detail/work_items/next_step/deliverables 可选且往返一致；`fstar state show` 降级显示不报错；阶段与运行状态相互独立。
- 判定方式：machine。
- 检查方法：实测 + 来源核实：schema 数例、旧任务读取、新字段往返、state 输出与 evidence 快照不受影响。
- 证据要求：测试命令与输出、样例 task.json 前后对比；覆盖缺字段旧任务与全部新字段任务。
- 判定边界：仅新任务可读或旧任务报错均不满足；字段存在但未参与显示/兼容用例不算完整满足。

### A-002 按需文档与扁平任务目录

- 依据：C-09（不默认生成 PRD/design、无固定 doc/ 概念）、C-13（正式交付需 criteria 与检查记录）、C-22（检查记录按序归档），见 [澄清记录](clarify.md)；计划 [S-1](plan.md)。
- 场景与期望：正式交付在根目录生成 criteria.md；简单事项以 task.json + criteria 即可推进，不强制 clarify/plan；clarify/plan 按不确定性与交接需要生成；检查记录固定放入 checks/ 并按序号递增；research/subagents 的单份结论直接写根目录单文件，仅内容确实多时才展开为目录；默认模板集不再含 doc/prd、doc/design。
- 判定方式：machine。
- 检查方法：实测 + 对照检查：模板内容、默认生成路径、简单事项与复杂事项的目录样例。
- 证据要求：生成样例目录树、模板清单与来源；旧默认生成路径无残留的检索结果。
- 判定边界：仅目录变平但仍强制固定文件组合，或把 checks 记录拆成根目录单文件/按需目录，均不满足；归档历史保持原样不作为失败。

### A-003 授权范围内任意位置交付编辑与基线安全

- 依据：C-09（交付位置由用户偏好决定）、C-10（保留原件与顺序）、C-11（后台编辑派发带版本/依据/范围），见 [澄清记录](clarify.md)；计划 [S-1/S-3](plan.md)。
- 场景与期望：文档编辑作用于受授权项目内用户指定位置的指定交付文件与部分（项目外路径不在本工作流实现与验收范围，不宣称支持），不依赖固定 doc/ 路径；派发携带精确允许路径白名单、输入指纹与基线；输入已变化时返回冲突而不覆盖；交付指针登记可追溯到实际位置与版本。
- 判定方式：machine。
- 检查方法：实测 + 对照检查：项目内非 doc/ 路径编辑、白名单外写入、旧基线冲突、交付注册指针一致性。
- 证据要求：编辑前后哈希、冲突返回记录、越界未写入证据、交付注册内容。
- 判定边界：能编辑任意文件但无基线/越界检查，或超出精确白名单与项目范围却宣称支持，均不满足；仅凭路径存在不证明防覆盖。

### A-004 实施与检查角色分离

- 依据：C-11（主 Agent 协调、后台派发）、C-12（角色按能力复用、全新实例检查）、C-21（大任务按标准条目并行检查），见 [澄清记录](clarify.md)；计划 [S-3](plan.md)。
- 场景与期望：生产修改由派发实施者完成，验证由非生产者独立检查；重要检查使用全新实例；大任务可按 criteria 条目拆分给并行检查者，汇总由单一检查者或主 Agent 负责；检查者引用条目编号与证据，缺陷交回执行者修复。
- 判定方式：machine。
- 检查方法：实测 + 对照检查：派发输入/返回字段、检查者上下文独立性、并行分片与汇总记录。
- 证据要求：派发与检查记录、标准条目到检查者的映射、缺陷回归修复记录。
- 判定边界：同一实例既改又判不满足；并行按文件切分或无人对整体负责不满足。

### A-005 局部复验与最终只读检查

- 依据：C-12（最终检查只读）、C-21（并行检查与最终汇总）、C-22（检查记录按序归档），见 [澄清记录](clarify.md)；设计 §5 与计划 [S-4](plan.md)。
- 场景与期望：需求或成果变更后默认全量作废并复验；仅当派发明确给出 localized 失效范围时，才按受影响 criteria 条目及其依赖局部作废；未明确范围一律按保守全量处理，不宣称系统自动推导语义影响；任何复验后的变更都要求新的最终只读检查；最终检查允许范围为空、产生 changed_paths 的记录被拒绝；检查记录在 checks/ 按序号递增。
- 判定方式：machine。
- 检查方法：实测 + 反例：明确局部范围、依赖蔓延、未给范围、最终检查写入被拒、序号归档。
- 证据要求：变更前后条目状态、派发中的失效范围、最终检查 read_only 标记与事件日志、拒绝记录、checks/ 文件序列。
- 判定边界：未给范围却声称局部作废、超出范围失效条目、或最终检查无内核拒绝证据，均不满足；全量作废是允许的安全默认，但明确局部范围时必须能按条目及依赖失效。

### A-006 用户验收与规则自验收门槛

- 依据：C-02（用户决定目标/范围/标准/授权）、C-12（最终检查独立）、C-15（硬规则与推荐分离），见 [澄清记录](clarify.md)；现行 [routing](../../../resources/runtime/routing.md) 的验收规则。
- 场景与期望：验收仍由用户明确完成；只有已记录规则明确覆盖该类工作时，才可引用规则自验收，且须全部条目 machine 可验、有证据、无 user-judgment 项，并执行门槛检查、自验收报告与 never-covered 清单；无规则匹配时不得豁免；最终检查新鲜本身不等于验收。
- 判定方式：machine。
- 检查方法：实测 + 反例：命中规则、未命中规则、含用户判断项、证据缺失、优先级或风险理由。
- 证据要求：规则原文与匹配依据、条目判定方式清单、自验收报告、accepted_via_rule 记录；反例应显示拒绝。
- 判定边界：任一 user-judgment 条目、无规则或仅凭检查通过，均不得判满足。

### A-007 意图驱动的技能选择协议

- 依据：C-23（每阶段及 no_task 按意图优先使用本地技能），见 [澄清记录](clarify.md)；计划 S-5 与 [S-5 规格](s5-spec.md)。
- 场景与期望：公共 routing 在需求澄清、实施、验收、完成及 no_task 均要求先判断意图与范围，优先用户点名技能，读取适用规则后实际调用再继续；每个用户回合有轻量提醒且保留阶段提示；派发传递选择及理由，worker 可补充并返回回执或未调用原因；无匹配正常推进，普通歧义合理默认，防递归 fstar 调用，不自动安装或把可用/推荐当已调用。
- 判定方式：machine。
- 检查方法：实测 + 对照检查：协议集成测试覆盖全部 prompt 状态与降级、派发往返、无匹配/多候选、防递归与失败回执；不得以关键词路由或字符串断言替代行为验证。
- 证据要求：hook 输入/输出、派发字段、worker 回执；真实宿主证据按 A-008 单列。
- 判定边界：仅提醒注入、仅字符串匹配或 fake 回执，只算协议部分满足，不能整条判通过。

### A-008 技能选择的真实宿主有限案例

- 依据：C-23 与 C-19（能力/适用性/实际验证分离），见 [澄清记录](clarify.md)；[S-5 规格](s5-spec.md) 验收条目。
- 场景与期望：在真实宿主中完成有限案例：用户点名技能、跨阶段/no_task、无匹配、多候选、worker 补充并使用；记录实际暴露技能、读取与调用及后续结果；不可用或未调用如实说明，不报成功。
- 判定方式：machine。
- 检查方法：实测：逐场景记录宿主输入、候选技能、实际调用、输出与限制，并按调用记录与宿主输出客观复核；与协议测试结果分开汇总。
- 证据要求：宿主版本/来源、调用记录或日志、场景输入输出；未执行场景明确标“未验证”。
- 判定边界：fixture、模拟回执或字符串断言不得充当真实调用；只测部分场景只覆盖该范围，不代表通用语义可靠。

### A-009 四能力接口、缺席降级与分发兼容

- 依据：C-14（核心自足、外部工具经适配接入）、C-19（安装配置/使用经验/操作授权分离），见 [澄清记录](clarify.md)；设计 §6 与 [S-5 规格](s5-spec.md)。
- 场景与期望：会话管理、能力分发、记忆存储、调度触发均有可注入的探测/握手/降级接口；缺席或握手失败分别降级为主会话、宿主原生 skills/hooks、既有本地知识存储、手动驱动，核心流程继续；探测/握手不自动执行或授权；既有 Magpie 安装分发作为适配实现，保留公开 API、CLI、原生安装/更新/doctor 行为。
- 判定方式：machine。
- 检查方法：实测：fake adapter 合同测试、无外部适配的核心链路、Magpie 安装分发回归与 API/CLI 对照。
- 证据要求：各能力可用/不可用/失败结果与原因、调用次数/副作用断言、安装与命令输出；fake 只证明合同。
- 判定边界：仅接口存在而无降级路径不满足；分发成功不得表述为运行时技能已调用。

### A-010 经验范围、纠正与停用闭环

- 依据：C-04（个人/场景/事项范围）、C-18（纠错/过期/退出、来源与置信度可追溯）、C-19（三类权威分离），见 [澄清记录](clarify.md)；计划 [S-6](plan.md) 与 [S-6 规格](s6-spec.md)。
- 场景与期望：经验条目带 scope、置信度（明确要求/推测/已验证）、来源引用与失效条件；读取按当前事项意图/范围过滤，不通过显式 documents 引用绕过停用/失效；用户可经既有授权提案管线纠正更新，旧记录与来源保留可审计；停用或机器可判到期后不再注入；推测不默认升级为规则；技能偏好仅作为普通经验候选。
- 判定方式：machine。
- 检查方法：实测：临时项目内沉淀→按范围读取→纠正→停用/到期复查；自然语言失效条件标注 unknown；旧知识/索引/预算/路径安全回归。
- 证据要求：学习与提案/确认记录、过滤前后注入清单、纠正前后文件与索引、停用/到期原因；全部使用临时 fixture。
- 判定边界：仅字段落盘而无过滤或纠正/停用闭环不满足；自然语言条件不得伪装机器判定。

### A-011 旧安装升级与完整生命周期

- 依据：C-06（task.json 状态权威）、C-14（核心自足）、C-19（权威分离）、C-20（协作成本与停止条件），见 [澄清记录](clarify.md)；计划 S-1..S-6 与 AGENTS.md 的安装/资源清单规则。
- 场景与期望：从既有全局安装升级后，安装/更新/doctor 正常，原生 Magpie 安装与资源迁移路径不被破坏；资源清单幂等且与构建一致；旧任务、旧知识文档、索引、预算与路径安全继续工作；完整生命周期（建任务→澄清/标准→实施→独立检查→用户验收→归档或恢复）可走通；schema 迁移只经显式迁移命令。
- 判定方式：machine。
- 检查方法：实测 + 对照检查：安装/升级/doctor、manifest 重建、旧数据读取、生命周期 e2e、迁移分离。
- 证据要求：命令与退出码、升级前后版本/资源清单、旧任务与知识读取结果、e2e 记录；影响面覆盖 hook、派发、验收与归档。
- 判定边界：仅新装可用或需手工删数据才能升级，不满足；资源更新与 schema 迁移混作副作用不满足。

### A-012 范围边界与发布状态

- 依据：C-08（第一版边界、调度后续）、C-14（外部工具可替换）、C-05（轻量对话不强制建任务），见 [澄清记录](clarify.md)；计划 [状态说明](plan.md)。
- 场景与期望：不实现调度器/herdr 集成、云记忆同步、自动习惯记录或 Python 内 LLM 推理；未确认事项不写成已批准；用户验收前不合并、不发布，版本只在 release 流程按 npm 对齐；README 与发版同步留待用户验收后的 release 流程。
- 判定方式：machine。
- 检查方法：对照检查：实现与资源差异、命令/版本输出、分支与发布记录、文档措辞。
- 证据要求：差异路径清单、版本与分支输出、发布记录（应为空）；越界项有明确说明。
- 判定边界：存在上述范围外实现即不满足；展示内容不等于用户批准；未发布不得被表述为发布。
