# 通用阶段工作流与经验循环：实施计划

来源：[澄清记录](clarify.md)（C-01..C-23）与[技术设计](doc/design.md)（用户已评审通过，2026-11-21"好没问题了"）。C-23 的追加方案及继续实施已获用户明确授权，原话见澄清记录；S-5 细化见 [S-5 规格](s5-spec.md)。

## 整体思路

按设计 §8 的六步切分，每步独立可验收。第一版核心是前三步（对话驱动工作流：模板、schema、Skills/路由），后三步按价值排序推进。原计划按 CONTRIBUTING 分支规范逐步独立分支，全量回归绿 + 用户验收后合并；当前实际工作树与尚未合并/发布的状态见末尾说明，不把原计划写成已执行事实。

设计中的四个开放问题（design.md §9）在对应步骤的计划细化为具体方案；方案若影响用户约定，回到澄清记录补充确认。

## 步骤

**S-1 模板与验收流程（纯资源改动，风险低）**
- 输入：设计 §2，样稿组。
- 行动：重写 task/plan、task/clarify 模板；新增 criteria 模板；check 模板补三线结论与拆分汇总；prd/design 移出默认集转场景参考；更新 plan.mapping.yaml；`node scripts/build-package.cjs` 重建清单。
- 产出：新模板集 + 对应 content 测试更新 + manifest。
- 完成判据：全量 Python/Node 测试绿；模板内容与样稿结构一致；无旧默认生成路径残留。

**S-2 task.json schema 扩展**
- 输入：设计 §4 字段草案。
- 行动：实现 status/status_detail/work_items/next_step/deliverables 可选字段；旧任务默认值兼容；`fstar state show` 展示新字段；schema 版本评估（是否触发 migrate）。
- 产出：内核字段支持 + 兼容测试（旧任务读写、新字段往返、evidence 快照不受影响）。
- 完成判据：现有测试零回归；新字段读写与降级显示有测试覆盖。

**S-3 Skills/角色卡/routing 重写**
- 输入：设计 §3。
- 行动：重写五组 Skills 与四张角色卡；routing.md 收缩为 C-15 硬规则 + 推荐做法；软路由 magpie 分发适配新资源清单。
- 产出：新资源集 + routing 硬规则清单。
- 完成判据：新 Skills 与模板/schema 一致；routing 不再含已移除的强制流程；安装/更新/doctor 全链路测试绿。

**S-4 验收协议改动（改现有 rework 语义，需单独验证）**
- 输入：设计 §5。
- 行动：最终检查只读约束；rework/证据失效按标准条目局部化；accepted_via_rule 引用适配 criteria 条目。
- 完成判据：局部作废与全量作废的场景测试；验收流程 e2e 更新。

**S-5 意图驱动的本地技能选择与工具适配接口**
- 输入：C-14/C-19/C-23、设计 §6、[S-5 规格与标准](s5-spec.md)；S-1～S-4 阶段确认作为已有基线。
- 行动（先做技能选择）：公共 routing 定义所有阶段及 no_task 的意图→宿主暴露技能元数据→读取适用规则→实际调用→继续推进；prompt-context 每轮加共用轻量提醒，不加载全部正文；派发协议与角色卡传递所选技能及理由，worker 可补充匹配，返回实际调用回执或未调用原因。主/子 Agent 负责语义判断，Python 不做关键词路由或 LLM 推理。
- 行动（再做适配）：用薄接口表达会话管理、能力分发、记忆存储、调度触发的探测/握手/降级；已有 Magpie 安装分发成为能力分发适配实现，保留原生安装路径、既有公开 API/CLI。其余缺席时分别沿用主会话、宿主原生 skills/hooks、既有本地知识存储、手动驱动；不实现调度器或 herdr 集成。
- 产出：公共路由与提醒、派发/角色协议、可注入适配接口及兼容实现、对应测试和分层证据；不引入自动安装或 S-6 的偏好学习。
- 完成判据：逐项核对 S5-A01..S5-A10；覆盖点名技能、跨阶段/no_task、无匹配、多候选、worker 使用与缺席降级。确定性集成测试及 fake adapter 仅证明协议行为；真实宿主实际调用单列证据和已验证/未验证状态，不能用字符串断言或模拟输出声称语义匹配可靠。针对性测试、全量 Python/Node 与 manifest 幂等通过，影响检查覆盖安装/更新/doctor、hook、派发及原有验收边界。
- 遇阻：文档输入指纹冲突交回协调者；真实范围缺口才重新澄清。普通候选歧义采用合理默认，适配缺席按已定降级继续；缺少真实宿主调用证据如实报告，不冒充完成。

**S-6 经验循环增强**
- 行动：经验条目增加 scope/置信度/失效条件字段；检索按事项范围过滤；修正与停用命令。
- 完成判据：沉淀-调用-修正-失效闭环测试；用户纠正可更新旧经验。

S-1..S-3 为第一版核心（C-08）；S-4..S-6 完成第一版核心验收后按价值排序启动。

## 验证与交付

每步：针对性测试 + 全量 Python/Node + manifest 幂等；README 同步更新（发版前完整校对，含记忆中的 README-on-merge 规则）。独立检查遵循当前有效协议；原定“S-4 合入后切换”是早期迁移设想，S-4 已在当前工作树实施并获阶段确认，不表示已合入或宿主安装已更新。发布走 release 分支 + npm 对齐，当前仍按用户要求推迟。

## 调整条件

- S-2 兼容分析发现 evidence/lease 深度耦合 → 停下补设计，不硬迁移。
- S-4 局部作废方案影响验收安全性 → 保留全量作废并报告取舍。
- 任一步全量回归无法保持绿 → 该步不合入，单独修复。
