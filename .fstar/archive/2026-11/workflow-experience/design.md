# 工作流体验改进：设计工作稿

依据 clarify.md 和 criteria.md。本文是实现指导，尚未声称实现或验证通过；设计与事实发生偏差时更新。

## 架构边界

一个 Git linked worktree 应同时具有两个互不混淆的上下文：

1. 当前执行 checkout：路径、分支、提交、工作目录和按当前分支版本化的项目索引与规范。
2. 稳定项目身份及共享任务数据根：同项目 task、状态、事件、锁及归档；每个会话的当前任务选择仍应保持会话隔离。

不能只把所有 project_root 替换为主工作树：那会误读其他分支的规范并错误记录执行分支；也不能把所有数据指向当前 worktree，否则任务会分叉。采用显式上下文贯穿 CLI、hook、知识解析、派发和证据，并保留旧接口兼容。

## Worktree 与旧数据

- project-shared：安全识别已跟踪的空项目骨架时，共用主项目任务数据，读取执行 checkout 的版本化规范；独立任务、不同身份或冲突指针不得被隐藏、覆盖或合并。
- project-local、user-directory、显式独立项目、嵌套项目、坏指针、不可达主工作树必须保留可诊断的原有身份与数据。规范不在分支中时如实显示实际来源，不伪称有分支版本。
- 只读诊断给出双方身份、路径与冲突；迁移、合并、覆盖或删除不作为自动识别的副作用。
- 任务记录实际执行 worktree 和分支；共享任务的锁基于同一稳定数据根。

## 知识沉淀与加载

- 识别持久偏好、重复要求、纠正或经过验证的可复用流程时，自动派发专门后台沉淀角色，主会话继续；区分候选、已派发、已写入、失败、待确认。归档时检查可访问对话、纠正和任务资料，诚实报告无法访问或截断的来源。
- 按可证实的适用范围推荐用户级或项目级；准备提案、解决冲突和写入复用现有知识机制，遵循用户授权。
- 会话注入顶层索引；协调者按任务语义选择主题索引和正文，派发时传递明确的规范来源与指纹。程序校验安全路径、缺失、冲突和预算，不以已选代替实际读取。

## 任务文档及角色

持久开发任务默认 plan 作为执行入口，引用 criteria、适用规范及按复杂度生成的 design；session-only 简单事项保持轻量。适用时选择对应 fstar 后台角色，明确实际调用、不可用及失败；确定性检查交给脚本，语义识别不冒称有确定性保证。

## 实施与验证

按 plan.md 分步实施。worktree 需真实 Git linked worktree 场景：跨工作树任务读写、分支差异、身份冲突、坏指针、旧数据及各存储模式。知识和角色需验证安装升级、资源版本、正文加载、后台派发、缺失与授权；人工场景检查语义识别。按影响检查指南核对调用方、证据、锁、归档、事件压缩、安装和读取预算；完整运行适用测试及构建资源清单，独立检查后如实报告限制。
